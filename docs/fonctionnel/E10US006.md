# E10US006 — Modifier l'identifiant ou le mot de passe administrateur

> Documentation fonctionnelle — **scénario de test pour un utilisateur non technique**.
> Objectif : depuis l'application, **changer** l'identifiant et/ou le mot de passe de l'accès
> administrateur, sans ouvrir le fichier `.env` ; vérifier que **l'ancien mot de passe ne sert
> plus**, que **les autres appareils** connectés en administrateur sont **déconnectés**, et qu'une
> erreur de saisie **ne vous déconnecte pas**.
> Suivez les étapes dans l'ordre ; comparez à chaque fois ce que vous voyez au « résultat attendu ».

## Fonctionnalité concernée
L'accès administrateur (fiche E10US002) se change désormais depuis l'écran **« Compte
administrateur »**, dans l'axe **« Atelier »** de l'administration. Le **mot de passe actuel** est
toujours demandé. Le fichier `.env` reste la **porte de secours** en cas d'oubli.

## Pré-requis
- L'accès administrateur est déjà défini (fiche E10US002), identifiant *« orga »*, mot de passe
  *« ancien »* dans les exemples ci-dessous.
- **Deux appareils** (ou deux navigateurs différents) : un **appareil A** et un **appareil B**, tous
  deux connectés en administrateur.

## Scénario A — Changer le mot de passe

1. **Ouvrir l'écran.** Sur l'appareil A, dans l'administration, choisissez l'axe **« Atelier »**,
   puis **« Compte administrateur »** dans la colonne de gauche.
   → *Résultat attendu :* quatre champs — **« Mot de passe actuel »**, **« Nouvel identifiant (vide
   = inchangé) »**, **« Nouveau mot de passe (vide = inchangé) »**, **« Confirmer le nouveau mot de
   passe »** — et un bouton **« Enregistrer »**, inactif.

2. **Remplir.** Mot de passe actuel : *« ancien »*. Nouveau mot de passe et confirmation :
   *« nouveau »*. Laissez l'identifiant vide.
   → *Résultat attendu :* le bouton **« Enregistrer »** devient actif.

3. **Enregistrer.**
   → *Résultat attendu :* le message *« Identifiants modifiés. Les autres appareils connectés en
   administrateur ont été déconnectés ; celui-ci reste connecté. »* ; les champs se vident ;
   l'appareil A reste dans l'administration.

4. **Vérifier l'appareil B.** Sur l'appareil B, **enregistrez** quelque chose (par exemple créer
   un club dans l'Atelier). Une simple consultation ne suffit pas : les lectures sont publiques,
   l'appareil B ne découvre sa déconnexion qu'à sa première écriture.
   → *Résultat attendu :* l'enregistrement est refusé et l'appareil B revient à l'écran de
   **connexion**.

5. **Vérifier les mots de passe.** Sur l'appareil B, essayez de vous connecter avec *« orga »* /
   *« ancien »*.
   → *Résultat attendu :* refusé (*identifiant ou mot de passe invalide*). Avec *« orga »* /
   *« nouveau »* : la connexion réussit.

## Scénario B — Changer seulement l'identifiant

1. Sur l'écran **« Compte administrateur »**, saisissez le mot de passe actuel, puis un **nouvel
   identifiant** (*« arbitre »*), sans toucher aux champs de mot de passe. Enregistrez.
   → *Résultat attendu :* le message de succès. À la prochaine connexion, *« arbitre »* avec le
   même mot de passe fonctionne ; *« orga »* ne fonctionne plus.

## Scénario C — Les erreurs ne vous déconnectent pas

1. **Mot de passe actuel faux.** Saisissez un mot de passe actuel erroné et un nouvel identifiant,
   puis enregistrez.
   → *Résultat attendu :* un message rouge *« Le mot de passe actuel est incorrect. »* ; vous
   **restez** sur l'écran, connecté ; rien n'a changé (l'ancien accès fonctionne toujours).

2. **Confirmation différente.** Saisissez deux nouveaux mots de passe différents.
   → *Résultat attendu :* dès que la confirmation est saisie, le message *« Les deux nouveaux mots
   de passe ne correspondent pas. »* ; le bouton reste **inactif**. Tant que la confirmation est
   vide, aucun message, mais le bouton reste inactif.

3. **Rien à changer.** Saisissez seulement le mot de passe actuel, ou un « nouveau » mot de passe
   identique à l'actuel.
   → *Résultat attendu :* sans nouvelle valeur, le bouton reste **inactif** ; avec une valeur
   identique, un message rouge *« Les nouveaux identifiants sont identiques. »*, et vous restez
   connecté.

## Rattachement aux critères d'acceptation (`stories/E10-acces-roles.md`, E10US006)
